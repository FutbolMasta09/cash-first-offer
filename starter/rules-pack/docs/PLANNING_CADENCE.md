# Planning Cadence

Simple recurring rhythm to stay on track without process overload.

## Dual-Project Operating Rule

Which project is primary is decided by the project's own governing records and the current workspace/studio portfolio authority — this document never infers or assigns a primary build. When a primary and a secondary project run in parallel:

1. **The primary project always comes first.**
2. Secondary-project planning/build starts **after** the primary project's daily must-ship work is done.
3. If the primary project falls behind, the secondary project pauses for the week except critical planning hygiene.

## Weekly Review (20 Minutes)

Run once per week.

1. Run one **combined** Saturday planning pass for both projects.
2. Check roadmap movement and blockers for the primary project first, then the secondary.
3. Lock one must-ship item per project (secondary second).
4. Note one cross-project risk to reduce this week (scope drift, context switching, budget burn).

Output:
- Updated weekly priorities for both projects in tracker/docs
- Capacity split for next week (e.g., 80/20 or 70/30)
- One risk mitigation action

## Milestone Review (30 Minutes)

Run when a phase milestone is completed.

1. Update `ROADMAP_TIMELINE.md`.
2. Update `ESTIMATION_RETROSPECTIVE.md` (safe vs actual delta).
3. Update `FORECAST_BASELINES.md` only if patterns repeat.
4. Run rule upgrade pass and rebuild rules pack.

Output:
- Forecast accuracy update
- Updated multipliers (if justified)

## Monthly Strategy Refresh (30 Minutes)

Run once per month.

1. Run one combined monthly strategy refresh for both projects.
2. Review `STRATEGY_HORIZONS.md` and confirm the primary project's launch protection first.
3. Review secondary-project status against primary-project risk (no priority inversion).
4. Move one deferred item forward only if primary-project timeline risk stays controlled.
5. Run short project-specific execution checks separately if needed (forecast/roadmap deltas).

Output:
- Refreshed horizon priorities for both projects
- Clear "do now vs later" boundary
- Explicit keep/pause decision on secondary-project pace for next month
