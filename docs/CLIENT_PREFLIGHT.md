# Client preflight — master sheet (Package A & B)

**Purpose:** Collect **everything** from the client in **one shot** so Ryan is not blocked waiting on follow-up questions.  
**Hard gate:** Do **not** start building until the matching intake form below is **100% complete** (and for B, the one-page brief is approved). Incomplete = polite “waiting on intake” status, not partial work.

**Rule:** Prefer **client-owned accounts**. Ryan never needs the client’s email password. Use invites, magic links, or screen-share while **they** stay logged in.

Update this file when a real job teaches a new gotcha.

---

## How Ryan uses this

1. Payment/deposit clears.
2. Send the **full** Package A or B intake block (copy-paste below) in **one** message.
3. When they reply, paste answers into a client note (separate client repo for B; private note for A).
4. Only then schedule build/handoff.
5. If anything is blank, send **one** chase: “Still need items X, Y, Z — I start when the form is complete.”

**Ryan never asks for:** email passwords, bank logins, social media passwords, or API keys in chat.
