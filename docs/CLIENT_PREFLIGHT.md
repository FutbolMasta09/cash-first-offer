# Client preflight — master sheet (Package A & B)

**Purpose:** Rules, gates, and blockers so Ryan is not stuck mid-build.  
**Sendable questionnaires:** Amber-style master template → [`CLIENT_INTAKE_TEMPLATE.md`](CLIENT_INTAKE_TEMPLATE.md)  
(duplicate / paste the form block; **never fill the template file itself**).

**Hard gate:** Do **not** start building until the matching intake is **100% complete** (and for B, the one-page brief is approved). Incomplete = polite “waiting on intake,” not partial work.

**Rule:** Prefer **client-owned accounts**. Ryan never needs the client’s email password. Use invites, magic links, or screen-share while **they** stay logged in.

Update this file when a real job teaches a new gotcha. Change the *questions* in `CLIENT_INTAKE_TEMPLATE.md`.

---

## How Ryan uses this

1. Payment/deposit clears.
2. Open `CLIENT_INTAKE_TEMPLATE.md` → copy the **Package A or B client form** block only → send in one message (or duplicate per that file’s “How to use”).
3. When they reply, store answers **outside** this offer repo for A (private note); for B, in the **separate client repo** (`docs/GROWTH.md`).
4. Run the Ryan-only checklist in the template. Only then schedule build/handoff.
5. If anything is blank, send the chase template once from the intake template.
6. Log a **non-PII** line under Completed Intakes in the template.

**Ryan never asks for:** email passwords, bank logins, social media passwords, or API keys in chat.
